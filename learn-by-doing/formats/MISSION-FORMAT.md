# MISSION.md 模板

## 原则

- **Why 必须真实**：不是为了学而学，而是为了解决一个问题
- **Success looks like 必须可验证**：不是"理解 X"，而是"能运行 X 并输出 Y"
- **Out of scope 要明确**：防止项目膨胀

## 模板

```markdown
# Mission: {项目名称}

## Why

一句话说清学这个能做什么。

## Success looks like

- [ ] {可验证的验收标准 1}
- [ ] {可验证的验收标准 2}
- [ ] {可验证的验收标准 3}
- [ ] {可验证的验收标准 4}
- [ ] {可验证的验收标准 5}

## Constraints

- 时间：{时间限制}
- 环境：{操作系统、工具版本等}
- 前提条件：{需要先掌握什么}

## Out of scope

- {这轮不碰的模块 1}
- {这轮不碰的模块 2}
```

## 使用规则

- **不要替用户写 Why** — 引导用户自己说
- **每条验收标准必须能用命令校验** — 不是"理解"，而是"执行 X 得到 Y"
- **修改 MISSION.md 前必须确认用户**
- **项目跑通后更新 MISSION.md，标记完成情况**
