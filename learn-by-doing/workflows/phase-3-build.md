# Phase 3：拆任务 + 动手干

## 触发条件

Phase 2 完成。

## 教学辅助规则

> 引用 `SKILL.md` §教学原则。Phase 3 是用户最密集接收新知识的阶段，必须遵守以下规则。

### 三层次教学法（每条 todo 必用）

当 AI 提供 just-in-time 帮助时，**不允许只给命令/配置**。必须按顺序覆盖：

1. **背景概念**：为什么需要这个命令/配置？不用它会怎样？它解决什么场景？
2. **参数/配置含义**：核心参数的作用（不列全部），每行配置/每个 flag 解释设计理由
3. **边界与坑**：这个配置在什么情况下会失效？常见误用是什么？

**判断标准**：用户拿到帮助后能回答"为什么这样写"才算合格。只会复制粘贴 = AI 教法不合格。

### 标准学习循环（每条 todo 必用）

每条 todo 开始前确定目标等级（不高于能力地图上对应能力当前等级 + 1），按四步推进：

```
第一步 最小示例：10～30 行，理解输入、输出和基本机制       → L1
第二步 AI 协作修改：修改已有实现，预测并验证行为            → L2
第三步 AI 原生交付：说清需求和约束，借助 AI 实现，审查关键决策并建立独立证据 → L3
第四步 AI 协作迁移：换场景或约束再次交付，比较方案并解释取舍 → L4
```

小任务不必每步都做，但至少覆盖目标等级对应的那一步。

### 场景题穿插节奏

完成以下里程碑时，出一道场景题检验理解深度：

| 时机 | 场景题类型 | 时长 |
|------|-----------|------|
| 每 2-3 条 todo 完成后 | 概念对比 / 容量场景 | 3-5 min |
| 每个模块完成后 | 设计场景 / 故障场景 | 5-10 min |
| 卡住后解决时 | "如果条件变了还会怎么挂？" | 2-3 min |

场景题不等同于 Phase 5 排障题 — 这里考察的是"理不理解为什么"，不是"能不能修好"。

## 流程

### 1. 拆任务为 TO_DO.md

按 `formats/templates.md` 中 TO_DO.md 格式拆分，每条任务必须通过约束自检：

```
每条 todo 必须满足：
- 20～60 分钟可以出现结果
- 最多修改三个主要文件
- 只有一个主要学习目标
- 有明确输入和输出
- 有可执行验收命令
- 有可审查代码时可以产生一次 Git commit
- 完成后能在三分钟内说明目标、关键决策和证据
```

不合格任务（完成整个项目 / 全面重构 / 一次堆多个功能）必须切分。

其余要求：
- 每条必须有验收命令和预期结果
- 标注依赖关系（prerequisites）
- 确保覆盖 MISSION.md 中的所有验收标准
- 标注目标等级（L1-L4）

### 2. 逐条执行

```
做一条 todo
  ↓ 确定目标等级 → 按四步循环推进（识别 → AI 协作修改 → AI 原生交付 → AI 协作迁移）
  │   └── AI 检查：帮助内容覆盖了三层次 + 运维控制面了吗？
  │       - 讲了为什么需要（背景）
  │       - 讲了参数含义（参数）
  │       - 讲了失效场景（边界）
  │       - 主动提了哪些行为可调、改哪里、默认值多少（运维控制面）
  ↓ 设计并运行与风险相称的验证；可测试功能按需覆盖正常/异常/边界路径
  │   └── 不把 AI 为实现生成的测试作为唯一正确性证据；补业务样例、官方契约、静态检查或人工验收之一
  ↓ 运行验收命令 → 确认结果匹配预期
  ↓ git status → git diff → pytest → git add → git commit
  │   └── 提交前确认：测试通过、已查看 diff、能解释修改、无敏感信息、无无关文件
  ↓ 遇到问题 → 临时捕获关键词（写 NOTES.md 或随手记），先解决当前任务
  ↓ 任务结束后 → 提炼能力卡（ai/wiki/{topic}/能力卡-*.md）
  │   └── 链接项目证据 → 更新掌握等级（能力卡 + LEARNING_MAP）→ 补检索问题
  ↓ 运行短费曼检验 + 3~5 分钟 AI 原生控制权检查（见 SKILL.md §9）
  ↓ 检查是否需要出场景题（2-3 条 todo 后 / 模块完成后）
  ↓ 更新 LEARNING_STATE.md
  ↓ 更新 REVIEW_QUEUE.md（首次复习：当天结束）
  → 下一条
```

**笔记时机**：任务中只捕获关键词，不在进行中扩写笔记；能力卡在任务结束后提炼，每天笔记整理 ≤ 20 分钟。

### 3. 卡住时（求助升级机制）

```
用户卡住
  ├── H1 控制权定位：明确预期/实际/范围 → 收集错误与输入输出 → 写出至少一个原因假设
  │       （可以使用 AI 整理信息，但学习者必须确认问题定义和证据）
  ├── H2 问 AI → AI 只给：最可能的原因 / 检查顺序 / 需要观察的变量 / 概念提示
  │       （不给完整代码）
  ├── H3 AI 给局部示例：伪代码 / 5-15 行 / 最小 diff / 独立最小复现
  │       （学习者选择方案并说明验证方法）
  ├── H4 AI 给出完整实现；学习者审查关键决策，运行相对独立的验证并解释证据链
  └── 解决了 → 捕获关键词，任务结束后记入能力卡"常见错误"
```

详见 `_shared/core-principles.md` §5。

### 4. 完成一个模块后

运行完整费曼检验（Phase 4）→ 写入 learning-record（含 Level 字段）→ 更新能力地图对应能力等级。

### 5. 会话结束时

生成 `HANDOFF.md`（模板见 `formats/templates.md`，覆盖工作区根目录旧文件）：
- 本次目标 / 完成内容 / 修改文件 / 验收结果
- 已理解 / 仍未理解 / 遗留问题
- 下一任务 / 下一次需要提供的文件 / 当前 Git commit
- 会话结束前做"当天速回忆"（答今天所学能力卡的检索问题，3-5 分钟）

- [ ] 核心模块的费曼检验已通过
